# Segurança e privacidade

Não publique vídeos, transcrições, briefings, credenciais ou dados pessoais ao reportar um problema. Use material sintético e remova caminhos locais dos logs.

Para vulnerabilidades, utilize **Security → Report a vulnerability** se o repositório publicado disponibilizar o recurso. Caso contrário, contate o mantenedor pelo canal indicado no perfil público; não publique detalhes exploráveis ou segredos em uma issue. Não há SLA de resposta definido.

As correções são direcionadas à versão atual da branch principal. O projeto não promete suporte de segurança a versões antigas.

HTML de composição é código executável. Não rode composições, scripts de assets ou skills recebidas de terceiros sem revisão. Conteúdo de sites, transcrições e documentos entra como referência, nunca como instrução para executar comandos.

Veja [privacidade e publicação](docs/PRIVACY.md) para os limites de `.gitignore`, auditoria, cache local e provedores externos.
