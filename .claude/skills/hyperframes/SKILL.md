# Repository video routing

Read AGENTS.md at the repository root. For footage editing, use ../video-edit/SKILL.md. This is the only editorial orchestrator.

- Existing project: read project.json and run node scripts/vid.mjs status <project>. Follow the current user request and preserve previous choices.
- Site/material supplied with footage: reference intake in video-edit; it does not change the deliverable into a product advertisement.
- Standalone motion graphics or an explicitly different deliverable: use general-video or motion-graphics with core and the necessary domain skills.
- Technical contracts: core for structure, animation/keyframes for motion, audio for mixing, creative for design, registry/media-use for assets. Load only what the task needs.
- Run the pinned CLI through node scripts/hf.mjs. Keep skills and CLI versions aligned. Upgrade/vendor operations happen only as explicit maintenance, never during an edit.
- Do not run upstream global skill installers, freshness routines, another transcript pass, or another intent interview. The upstream entrypoint is archived as reference, not an executable workflow for this repo.
- User authorization and review_policy govern approvals. Autonomously authorized work does not acquire extra approval gates from vendor documentation.
