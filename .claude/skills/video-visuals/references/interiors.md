# Interiors explanations

- Establish what the diagram represents: conceptual solution, specific project, dimensioned detail or before/after. Label a conceptual diagram when it could be mistaken for a built project.
- Keep one cabinet/room/object consistent while revealing width, height, internal organization and use. Use spatial relationships instead of generic SaaS cards.
- Number + unit + dimension axis must agree with the source. Width is not depth; external dimension is not usable internal clearance. Unclear spoken measurements require review before drawing a numeric label. Never infer exact height from “floor to ceiling.”
- Depict functional divisions correctly. Tall tools need a tall bay; a separately mentioned pantry should be a separate module. Illustrations must not imply an engineering specification absent from the source.
- Compare solutions using actual differences, and keep qualifications. “Less exposed to water in this installation” does not become “waterproof.” Use real project photographs when available and relevant.
- Favor visual restraint when the speaker is the trusted expert. Hands demonstrating size and the object being discussed deserve screen space. A diagram may briefly take the full frame; return to the person when expression matters.
- Build reusable primitives for dimensions, compartments, detail magnification and before/after. Choose palette/type from references, not from an assumed luxury or technology aesthetic.
